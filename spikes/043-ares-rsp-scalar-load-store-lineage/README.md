# Spike 043: ares RSP scalar load -> GPR -> store lineage

Status: experimental branch evidence. Run `python3 spikes/043-ares-rsp-scalar-load-store-lineage/run.py` from the repository root.

## Question

Can actual interpreted RSP scalar loads establish a concrete register generation that later scalar stores may consume, without inferring provenance from equal payload values? Does a whole-GPR writer sever that generation even if it recreates the same numeric value?

## Experiment

`driver.cpp` executes actual decoded RSP scalar programs with both recompilers disabled. It covers `LB/LBU/LH/LHU/LW/LWU` followed by `SB/SH/SW`, unaligned 4 KiB wrap, bit-12 DMEM aliasing, equal-valued loads from different locations, same-source reloads, same-value `ORI`/`ADDU` writers to the loaded GPR, and an unrelated writer.

The sensor build reuses the project-owned instruction-boundary and primitive DMEM-sink observer generated by spike 042. Instruction events capture the concrete pre/post GPR state. The observer issues no guest memory access, clock step, reset, serialization or reference-state write. Initial DMEM bytes are recorded explicitly before execution.

`verify.py` replays each decoded load from its pre-instruction base register and explicit DMEM state, checks the actual resulting GPR value, mints a fresh load generation, and follows that generation into later primitive store sinks. Whole-GPR writers not modeled as provenance-preserving transformations cut the generation regardless of numeric equality.

The verifier deliberately rejects forged histories and demonstrates two value-equality counterexamples:

- two distinct source words contain the same payload, so numeric equality cannot identify which load generation a later store consumed;
- `LW` loads `0x00001234`, then `ORI r2,r0,0x1234` recreates exactly the same value, yet the prior load generation must be dead.

## Neutrality

`run.py` builds and runs four cases:

1. uninstrumented baseline;
2. sensor binary with observers disabled;
3. sensor enabled;
4. enabled repeat.

All four must produce identical machine projections; the enabled runs must produce identical histories. The baseline and disabled sensor must have empty histories.

## Scope limits

This is a bounded exact-pin interpreter experiment. It does not prove a complete RSP GPR-writer census, provenance-preserving arithmetic transforms, vector-register loads, vector consumers, DMA composition, full scheduler/timing behavior, save/restore/reset mutation, hardware behavior, or whole-ROM executable closure. Gopher64 is source-compared only, not executed as a second behavioral oracle. The load source edge is reconstructed from the exact executed decoded instruction, pre-instruction GPR state, explicit DMEM replay state and pinned interpreter semantics; there is not yet a separate primitive DMEM-read callback.
