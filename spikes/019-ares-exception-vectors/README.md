# Spike 019: ares exception-vector roots

This spike tests one bounded executable-discovery question against the exact ares
revision pinned by `refs.lock.toml`:

> Which R4300 exception-entry virtual PCs can guest-triggered ordinary exceptions,
> TLB refill misses, TLB-invalid faults, nested exceptions, and delay-slot faults
> select as executable roots?

The harness runs the ares interpreter with synthetic post-initialization state and
no firmware. Faults are generated by guest instructions (or by an instruction
fetch through an empty TLB), not by calling exception helpers directly.

## Hypothesis

For the tested classes:

- ordinary exceptions and TLB-invalid faults enter the general vector at
  `base + 0x180`;
- a true TLB miss with EXL clear enters `base + 0x000` in 32-bit kernel mode and
  `base + 0x080` in 64-bit kernel mode;
- `BEV=0` selects base `0xffffffff80000000`, while `BEV=1` selects
  `0xffffffffbfc00200`;
- with EXL already set, even a true TLB miss enters the general vector and the
  prior EPC/BD state is preserved;
- a fault in a branch delay slot changes EPC/BD bookkeeping but not vector
  selection.

`tlb_invalid` is an adversarial case: it disproves the tempting but wrong rule
that every TLB-related exception uses a refill vector.

## Reproduce

```bash
python3 scripts/fetch_refs.py
python3 spikes/019-ares-exception-vectors/run.py
```

The runner requires `.refs/ares` to be exactly
`9408cb43d4948fc3ea6e152a307a34348df3fe04`. It builds through the existing
`spikes/003-ares-oracle/run.py` helper, executes every case twice, requires the
JSON states to match byte-for-byte, validates the truth table, and writes:

`target/ares-exception-vectors/results.json`

No ares CPU source is patched for this spike; only the existing headless build
wrapper used by spike 003 is reused. Generated build products and results remain
under `target/` and are not committed.

## Scope

This is not a closed-world proof for all R4300 exceptions. Interrupts, reset/NMI,
cache errors, watch exceptions, firmware/boot behavior, and arbitrary configured
TLB entries are outside this experiment. The result establishes only the tested
root-selection rule for the pinned ares revision, with independent source/test
cross-checks documented in `research/ares-exception-vectors.md` after execution.
